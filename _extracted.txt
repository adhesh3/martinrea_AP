Martinrea Finance AP System
Phase 1 — Foundation & Paperless
Netlink Software Group America | Version 1.0  |  May 2025
1. Executive Summary
Martinrea International operates 40+ manufacturing and processing locations across North America and faces significant challenges in its Accounts Payable function. These include decentralized operations, heavy reliance on manual document handling, no centralized visibility into invoice status, and absence of real-time performance metrics. The combination results in processing delays, compliance risk, and high operational cost.
Netlink has been selected as the development partner to build a cloud-hosted, AI-driven AP Automation Platform. The engagement is structured as a 3-Phase delivery. This document governs Phase 1 — Foundation & Paperless, which establishes the complete infrastructure, ingestion pipeline, AI-powered OCR processing, data repository, integrations with Epicor CMS, and the core human-assisted workflow for 3-way matching and electronic approvals.
Upon completion of Phase 1, Martinrea's AP team will transition from a paper-heavy, email-based, manually reconciled process to a digitized, centrally accessible, auditable workflow — reducing manual touchpoints and creating the foundation for full AI automation in Phase 2.

2. Business Context & Problem Statement
2.1 Current State Challenges
Challenge Area
Description
Decentralized Operations
40+ locations operate in silos with inconsistent AP processes, no shared system of record, and varying approval hierarchies across plants.
Manual Document Handling
Invoices, packing slips, and CMS receiving reports are processed manually — via email, physical mail, and shared drives — creating significant human error risk.
Processing Delays
Manual data entry and matching introduce delays in vendor payments, leading to missed early-payment discounts and strained supplier relationships.
Lack of Visibility
No centralized dashboard or status tracking. AP Managers cannot see where an invoice is in the lifecycle without contacting individual plant coordinators.
Inefficient Matching
2-way and 3-way matching is performed manually in spreadsheets. Inconsistent execution across plants results in duplicate payments and missed discrepancies.
Invoice Type Complexity
Multiple invoice types (Direct Voucher, Capital, Tooling, CFDI/Mexico) each require different handling rules, none of which are systematically enforced today.
Lack of Real-Time Metrics
No SLA tracking, exception rate visibility, or KPI dashboards. Leadership cannot measure AP performance or identify bottlenecks proactively.
Inventory & MRO Gaps
Min/max inventory levels are not frequently reviewed; missing resource IDs create reconciliation failures during matching.
2.2 Phase 1 Objectives
Phase 1 — Foundation & Paperless aims to achieve the following measurable outcomes:
Eliminate paper-based invoice receipt — 100% of invoices enter through digital channels (email, SFTP, portal).
Establish a centralized, searchable document repository with full audit trail.
Automate OCR/AI data extraction from invoice images and PDFs, reducing manual keying by >80%.
Provide a structured, UI-driven 3-way matching workbench for AP Clerks (manual matching with system-assisted discrepancy detection).
Implement role-based electronic approval workflows with escalation and SLA enforcement.
Integrate with Epicor CMS (all 44 instances) for live PO, Supplier, and Goods Receipt data.
Implement CFDI validation for Mexico plants ensuring SAT regulatory compliance.

4.1 Track: Ingestion Epic
👤 Developer: Ayush
Track: Ingestion Epic
Objective: Automate the collection of invoices from external sources — Email (MS Graph), SFTP file drop, and web portal upload — into a centralized staging area for downstream OCR processing. This is the entry point of the entire AP platform.
ING-01 / ING-05 — Foundation & Pre-Processing Service
As a:  System Architect
I want to:  have a scalable ingestion backend service with pre-processing rules
So that:  files are validated before being saved to the repository, preventing corrupt or oversized documents from entering the pipeline
Acceptance Criteria
✓  Service initializes successfully in Node.js (NestJS runtime).
✓  Incoming files pass format validation — accepted types: PDF, JPG, PNG, TIF only.
✓  Files larger than 10 MB are rejected with a 400 error and a descriptive log entry.
✓  Files that fail validation are quarantined in a dedicated 'Rejected' Blob container.
✓  Validated files are handed off to Roshni's Azure Blob Storage write utility with metadata (source channel, timestamp, originating user).
✓  Service exposes a health-check endpoint (GET /ingestion/health) returning 200 OK.
ING-02 — Automated Email Ingestion
As a:  AP System (automated service)
I want to:  continuously monitor the designated AP email inbox and extract attachments
So that:  vendor email submissions are automatically queued without manual download by the AP team
Acceptance Criteria
✓  Service authenticates securely to Microsoft 365 via MS Graph API using OAuth 2.0 client credentials flow.
✓  Polling runs on a configurable schedule (default: every 5 minutes).
✓  All valid attachments (PDF, JPG, PNG, TIF) are extracted and pushed to Roshni's Blob Storage API.
✓  Processed emails are marked as 'Read' and moved to a 'AP-Processed' folder in the mailbox.
✓  Emails with no valid attachments are moved to 'AP-No-Attachment' folder for human review.
✓  Failed ingestion events (network timeout, auth failure) are logged and retried up to 3 times before alerting.
✓  No files are written to local server disk at any point.
💡 Dev Hint:  Use @microsoft/microsoft-graph-client npm package. Pass the file buffer directly to Roshni's Blob Storage upload function — do not write files to local disk. Ensure the OAuth token is refreshed automatically before expiry.
ING-03 / ING-04 — SFTP & Web Portal Ingestion
As a:  Mailroom Operator / AP Clerk
I want to:  drop bulk scanned invoices into a network folder or upload them via the web browser
So that:  physical invoices and portal submissions enter the digital queue without requiring manual email forwarding
Acceptance Criteria
✓  SFTP: Service polls the designated SFTP directory every 5 minutes using ssh2-sftp-client.
✓  After successful download and Blob upload, files are deleted from the SFTP source to prevent duplicate ingestion.
✓  SFTP: Failed downloads are retried up to 3 times; persistent failures generate an alert in the ops log.
✓  Portal: A REST API endpoint (POST /api/ingestion/upload) accepts multipart/form-data from Aditya's frontend.
✓  Portal upload returns a 201 response with a document ID and staging status for UI confirmation.
✓  Portal: File size and type validation mirrors the core pre-processing rules.
ING-06 — End-to-End Ingestion Testing

✓  Test cases include: valid file (success), oversized file (reject), invalid type (reject), duplicate file (idempotency check).

4.7 Track: Workflow & Approvals Epic
👤  Developer: Mohd Aman
Track: Workflow & Approvals Epic
Objective: Implement the role-based access control system, invoice lifecycle state machine, sequential approval routing engine, automated email notification service, and SLA escalation scheduler. This module is the governance backbone of the AP platform.
WF-01 / WF-02 — Role-Based Access Control & Lifecycle State Machine
As a:  System Administrator
I want to:  strict role definitions and a formally defined invoice status lifecycle
So that:  unauthorized users cannot approve invoices, and the system prevents any invoice from skipping mandatory workflow steps
Acceptance Criteria
✓  Authentication using JWT tokens; roles stored in the token payload and validated on every API request.
✓  Three roles implemented for Phase 1: AP_Clerk (full create/edit access), Plant_Manager (approval rights for invoices ≤$50K), Finance_Director (approval rights for all amounts).
✓  State machine strictly governs transitions. Permitted transitions: Received → OCR_Processing → Pending_Review → Pending_Match → Matched → Pending_Approval → Approved.
✓  Any transition not in the permitted list returns a 409 Conflict with a descriptive error.
✓  State machine transition events are logged to Audit_Logs with timestamp and user.
✓  Role-based UI rendering: Plant_Manager and Finance_Director see an 'Approve / Reject' action button; AP_Clerk does not.
✓  API-level authorization: Approval endpoints return 403 Forbidden if called by an AP_Clerk.
WF-03 — Sequential Approval Routing Rules Engine
As a:  Finance Director
I want to:  invoices above defined dollar thresholds to automatically require sequential approval from Plant Manager then Finance Director
So that:  financial oversight is maintained and large payments cannot be authorized by a single approver
Acceptance Criteria
✓  Routing rule 1: Invoice Total ≤ $10,000 → routed directly to Finance_Director (single approval).
✓  Routing rule 2: Invoice Total > $10,000 → routed to Plant_Manager first. Upon Plant_Manager approval, automatically routed to Finance_Director.
✓  Routing rule 3: Invoice Total > $50,000 → routed to Plant_Manager → Finance_Director → VP_Finance (future extension point defined in config).
✓  Rules are stored in a configurable Rules_Engine table — not hardcoded — so thresholds can be updated without code changes.
✓  System tracks: current_approver_id, approval_chain (JSON array of required approvers), approvals_completed (array of completed approvals with timestamp).
✓  Each approval step records: approver, decision (Approved/Rejected), timestamp, optional comments.
✓  Rejected invoices return to Pending_Review status with rejection reason visible to AP_Clerk.
WF-04 / WF-05 — Email Notifications & SLA Escalation
As a:  Plant Manager / Finance Director
I want to:  receive an automated email when my approval is required, and be automatically reminded or escalated to my manager if I do not act within the SLA window
So that:  invoice processing keeps moving without manual follow-up calls, and SLA violations are surfaced automatically to management
Acceptance Criteria
✓  System sends an SMTP email (via Nodemailer or Azure Communication Services) when an invoice transitions to Pending_Approval.
✓  Email contains: Invoice Number, Supplier, Amount, a direct deep-link to the approval screen, and the approval deadline.
✓  Email templates are HTML, mobile-responsive, and use Martinrea branding.
✓  A Cron job runs every hour (node-cron or Azure Logic Apps).
✓  If an invoice has been in Pending_Approval for >48 hours, an escalation email is sent to the current approver's manager.
✓  Escalation email clearly states: 'ACTION REQUIRED: Invoice [#] has been pending your approval for [X] hours and has been escalated.'

Comprehensive test strategy 
To ensure a defect-free rollout, Netlink applies a Shift-Left QA approach, embedding automated quality gates across the development lifecycle. Critical financial logic (matching, tolerances) and compliance rules (Tax / CFDI) are validated early—before reaching business users.
Design and execute application-level load and performance testing in non-production environments to simulate peak processing scenarios (e.g., month-end volumes). 
Identify performance bottlenecks, validate SLA assumptions, and provide tuning and optimization recommendations.
Production load testing execution remains subject to Martinrea environment readiness, access, and approvals.
